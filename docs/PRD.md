# PRD: Financial Company Comparison Agent

## 1. 产品概述

Financial Company Comparison Agent 是一个面向个人投资研究、金融学习和作品集展示的 AI 辅助分析工具。用户输入多个美股股票代码后，系统自动获取公开金融数据，完成指标清洗、维度评分、可视化对比，并生成自然语言分析报告。

产品核心目标不是直接给出投资结论，而是帮助用户更快完成公司基本面初筛，明确哪些公司值得进一步研究。

## 2. 背景与问题

个人用户在比较多家公司时，通常会遇到以下问题：

- 金融指标分散在多个网站，手动收集成本高。
- PE、PEG、ROE、收入增长、Beta 等指标维度多，横向对比不直观。
- LLM 可以生成分析文字，但如果缺少结构化数据约束，容易出现泛泛而谈或不可追溯的问题。
- 作品集项目常依赖外部 API，演示时容易受到 API Key、额度和网络环境影响。

因此，本产品将金融数据获取、结构化指标清洗、评分模型和 LLM 报告生成整合为一个可交互应用，并提供离线演示模式降低展示风险。

## 3. 产品目标

### 3.1 用户目标

- 快速比较 2-5 家美股公司的基本面指标。
- 通过图表理解估值、盈利能力、成长性和风险差异。
- 获取一份结构化 AI 分析报告，作为后续研究起点。
- 在无后端或无 API Key 环境下，也能完整体验产品流程。

### 3.2 业务目标

- 展示 AI Agent 与工作流编排在金融分析场景中的实际落地能力。
- 形成可演示、可复现、可扩展的作品集项目。
- 将「LLM 生成文本」升级为「数据驱动的分析产品」。

### 3.3 非目标

- 不提供买卖建议。
- 不承诺数据实时性或准确性。
- 不做完整投资组合管理。
- 不替代专业金融终端或投研系统。

## 4. 目标用户

### 4.1 个人投资学习者

希望快速了解多家公司的核心财务指标，并获得入门级分析框架。

### 4.2 数据分析 / AI 产品作品集评审者

关注项目是否具备清晰的业务问题、完整技术链路、可交互体验和可解释输出。

### 4.3 金融科技产品原型验证者

希望验证 AI Workflow 是否可以用于自动化金融信息整理和报告生成。

## 5. 使用场景

### 场景 1：科技股横向比较

用户输入 `NVDA, AAPL, MSFT`，选择「综合对比」，系统展示三家公司的市值、收入、盈利能力、成长性、估值和风险指标，并生成 AI 对比报告。

### 场景 2：估值专项分析

用户输入 3-5 个同行业股票代码，选择「估值分析」，系统重点比较 PE、Forward PE、PEG、Price to Sales、Price to Book 等指标。

### 场景 3：作品集离线演示

用户没有配置 Dify 或金融 API Key 时，选择「离线演示（无需后端）」，系统使用内置缓存数据展示完整 UI 和分析路径。

## 6. 用户流程

```text
进入 Streamlit 应用
        |

        |

        |
```

## 7. 功能需求

### 7.1 股票代码输入

**优先级：P0**

用户可以输入多个股票代码，使用英文逗号分隔。

验收标准：

- 支持输入如 `AAPL, MSFT, NVDA` 的格式。
- 空输入时提示用户补充股票代码。
- Dify Workflow 负责解析和规范化股票代码。

### 7.2 运行模式选择

**优先级：P0**

系统支持离线演示模式和 Dify API 模式。

验收标准：

- 离线演示模式无需 API Key 即可展示完整页面。
- Dify API 模式要求用户填写 Dify Base URL 和 API Key。
- 缺少必要配置时给出明确错误提示。

### 7.3 数据源选择

**优先级：P1**

在 Dify API 模式下，用户可以选择 Demo Mode、FMP 或 Live API Mode。

验收标准：

- Demo Mode 使用工作流内置样本数据。
- FMP 模式调用 Financial Modeling Prep。
- Live API Mode 调用 Alpha Vantage。
- 页面提示不同数据源需要的环境变量。

### 7.4 数据获取状态展示

**优先级：P0**

系统展示每个股票代码的数据获取结果。

验收标准：

- 成功项显示公司名称和成功状态。
- 失败项显示失败状态和错误说明。
- 如果没有任何成功数据，系统终止后续分析并提示用户。

### 7.5 公司概览卡片

**优先级：P1**

系统展示每家公司基础信息。

验收标准：

- 显示公司名称、股票代码、行业、板块。
- 显示 Market Cap 与 Revenue TTM。
- 支持 2-5 家公司横向展示。

### 7.6 核心指标表格与图表

**优先级：P0**

系统按分析维度展示核心金融指标。

验收标准：

- 估值与盈利能力页签展示 PE、Forward PE、PEG、EPS、Profit Margin、Operating Margin、ROE、ROA。
- 成长性与波动页签展示 Revenue Growth YoY、Earnings Growth YoY、52 Week High、52 Week Low、Beta。
- 分析师评级页签展示堆叠柱状图。
- 图表在桌面宽屏下可读。

### 7.7 研究优先级评分

**优先级：P0**

系统展示公司维度评分和综合评分。

验收标准：

- 展示成长性、盈利能力、估值匹配、波动风险、综合评分。
- 使用雷达图展示多维度差异。
- 使用表格展示排名和分数。
- 明确提示评分不构成投资建议。

### 7.8 逐家公司详情

**优先级：P1**

系统提供每家公司详细信息展开区。

验收标准：

- 展示公司描述。
- 展示市值、PE、EPS、Beta、Profit Margin、ROE、Revenue Growth、Earnings Growth。
- 默认折叠，用户可以按需展开。

### 7.9 AI 分析报告

**优先级：P0**

系统基于结构化数据生成自然语言报告。

验收标准：

- 报告使用 Markdown 渲染。
- 报告内容匹配用户选择的分析重点。
- 支持中文和英文输出。
- 报告区域明确说明由 Dify Workflow 后端 LLM 节点生成。

### 7.10 风险提示与免责声明

**优先级：P0**

系统在页面底部展示风险提示。

验收标准：

- 明确说明数据可能延迟、缺失或异常。
- 明确说明评分不代表投资建议。
- 明确说明本项目不构成买卖建议或收益承诺。

## 8. 非功能需求

### 8.1 可用性

- 用户无需阅读文档即可完成一次离线演示分析。
- Dify API 模式的必要配置应在侧边栏集中完成。
- 错误提示应具体到缺少 API Key、后端调用失败或数据为空。

### 8.2 可演示性

- 离线演示模式必须始终可用。
- 缓存数据应覆盖完整 UI，包括图表、评分和报告。
- README 应提供清晰启动步骤和作品集展示说明。

### 8.3 可维护性

- 前端不承担数据获取、清洗和评分逻辑。
- Dify Workflow 负责后端数据处理和报告生成。
- 前后端通过结构化 JSON 约定解耦。

### 8.4 安全与合规

- API Key 不应硬编码在前端代码中。
- Dify 环境变量应使用 secret 类型。
- 页面和文档必须包含非投资建议声明。

## 12. 风险与应对

### 风险 1：外部金融 API 限额

应对方式：

- 保留离线演示模式。
- 在页面中提示免费 API 额度限制。
- 支持多数据源切换。

### 风险 2：数据字段缺失或格式不一致

应对方式：

- 在 Dify Workflow 中做字段清洗。
- 前端对缺失字段展示 `N/A`。
- 数据为空时停止后续分析。

### 风险 3：LLM 输出不稳定

应对方式：

- 使用结构化数据作为报告输入。
- 在 Prompt 中限制报告维度和免责声明。
- 前端将评分与原始指标独立展示，避免完全依赖 LLM 文本。

### 风险 4：用户误解为投资建议

应对方式：

- README、PRD 和应用页面均明确声明不构成投资建议。
- 将评分命名为「研究优先级评分」而非「投资评分」。
- 强调结果只用于后续研究排序。

## 13. 作品集叙事角度

在作品集或面试中，可以将本项目描述为：

> 一个将公开金融数据、Dify Workflow、LLM 报告生成和 Streamlit 可视化整合在一起的 AI 金融分析原型。项目重点不是预测股价，而是展示如何把模糊的金融比较需求拆解为可执行的数据流程、可解释的评分模型和可交互的产品体验。

推荐展示顺序：

1. 说明用户痛点：多家公司基本面对比耗时且不直观。
2. 展示产品 Demo：输入股票代码并生成完整报告。
3. 讲解技术架构：Streamlit 前端 + Dify Workflow 后端。
4. 说明设计取舍：离线演示模式、结构化 JSON、研究优先级评分。
5. 讨论后续扩展：报告导出、财报原文、新闻分析和行业基准。
